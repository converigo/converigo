# Learning Center End-to-End SEO Audit

Date: 2026-07-21
Scope: Reviewed the Learning Center SEO flow across routing, templates, metadata, sitemap, canonical URLs, JSON-LD, breadcrumb schema, internal linking, robots compatibility, and mobile rendering assumptions.

Note: No code was modified.

## Summary

The Learning Center flow is generally functional for discovery and crawlability. The main routes are reachable, the pages render as HTML, robots.txt points to the sitemap, and the sitemap now includes Learning Center pages. The main SEO gaps are in structured data accuracy, breadcrumb consistency, and internal-link implementation.

## Verification Evidence

The following checks were run against the app:

- GET /learning -> 200 text/html
- GET /learning/what-is-file-conversion -> 200 text/html
- GET /learning/does-not-exist -> 404 application/json
- GET /robots.txt -> 200 text/plain
- GET /sitemap.xml -> 200 application/xml
- Test command: .\.venv\Scripts\python.exe -m pytest tests/test_sitemap.py tests/test_sitemap_service.py -q
  - Result: 3 passed, 1 warning

## 1. Router and Crawlability

### What is working
- The Learning Center routes are registered and reachable in [app/routers/learning.py](app/routers/learning.py).
- The index route at /learning returns HTML successfully.
- The article route at /learning/{slug} returns HTML successfully for an existing article.
- Missing articles return a proper 404 response.

### Assessment
- Discovery is working from a crawlability perspective. Search engines can reach the pages and receive valid HTML responses.
- The 404 behavior is appropriate for missing content and does not appear to create a crawler trap.

## 2. Metadata and Canonical URLs

### What is working
- The pages use the shared SEO metadata partial in [app/templates/partials/seo_meta.html](app/templates/partials/seo_meta.html).
- The template includes:
  - a title tag
  - a meta description
  - a meta robots tag
  - a canonical link
  - Open Graph tags
  - Twitter card tags

### Findings
- The router in [app/routers/learning.py](app/routers/learning.py) sets canonical URLs as https://converigo.com/learning and https://converigo.com/learning/{slug}, which is consistent and production-safe.
- However, the router does not appear to use the article-level canonical values that are already present in some article JSON files. The article data includes canonical values, but the router-generated metadata currently overrides them.
- This weakens consistency between the content layer and the rendered page metadata.

### Assessment
- Canonical handling is present and generally correct.
- The main issue is that the page layer is not fully honoring article-level canonical metadata.

## 3. JSON-LD / Structured Data

### What is working
- The learning pages include the structured data partial in [app/templates/partials/structured_data.html](app/templates/partials/structured_data.html).
- The router passes structured_data into the template context for both the index and article pages.

### Findings
- The structured data generation in [app/services/seo_service.py](app/services/seo_service.py) uses blog-oriented schema types for learning pages.
- For the learning index, it creates a Blog schema with a blogPost list, using the page data name and description.
- For the article pages, it creates a BlogPosting schema using the page_data values.
- A key issue is that the generated URLs in the structured data currently point to /blog/{slug} for learning article entries instead of /learning/{slug}.
- The breadcrumb labels for the learning index are also built as Home > Blog rather than Home > Learning Center.

### Assessment
- JSON-LD is present, but it is not yet fully aligned with the Learning Center routes.
- This is the clearest structured-data issue in the current SEO flow.

## 4. Breadcrumb Schema and Navigation

### What is working
- The article template includes a breadcrumb navigation in [app/templates/pages/learning_article.html](app/templates/pages/learning_article.html).
- The router builds a breadcrumb array for the article view.
- The SEO service also builds a breadcrumb list for JSON-LD.

### Findings
- The breadcrumb navigation is present in the page markup.
- The breadcrumb list in the rendered page is based on the router’s hard-coded structure rather than article-level breadcrumb overrides from the JSON content.
- The breadcrumb schema generated by [app/services/seo_service.py](app/services/seo_service.py) is not fully aligned with the Learning Center terminology.

### Assessment
- Breadcrumb structure is present and crawlable, but it is not yet fully consistent with the intended Learning Center information architecture.

## 5. Internal Links and Crawl Depth

### What is working
- The pages contain article sections and related-content sections.
- The Learning Center index provides links to article pages.

### Findings
- The related article, converter, and format blocks in [app/templates/pages/learning_article.html](app/templates/pages/learning_article.html) are rendered as cards with headings, but they are not actual anchor links to the referenced content.
- This weakens internal-link depth and reduces the value of the current article pages as crawl and ranking hubs.
- The learning templates do not currently provide a strong internal linking pattern that would guide crawlers from one article to the next.

### Assessment
- Internal navigation exists, but it is not strong enough to support a robust content hub structure.

## 6. Robots Compatibility

### What is working
- The robots endpoint returns a valid response at /robots.txt in [app/routers/seo.py](app/routers/seo.py).
- The robots file in [app/static/robots.txt](app/static/robots.txt) points to the sitemap and allows crawling.
- The sitemap URL is set to https://converigo.com/sitemap.xml.

### Assessment
- Robots compatibility is good. There is no evidence of blocking directives that would prevent the Learning Center pages from being discovered.

## 7. Sitemap Integration

### What is working
- The sitemap response returns successfully and includes Learning Center URLs.
- The sitemap regression tests now assert that /learning and /learning/what-is-file-conversion are present.

### Assessment
- Sitemap discovery is working for the Learning Center content.
- The integration is suitable for search-engine discovery.

## 8. Mobile Rendering Assumptions

### What is working
- The base layout in [app/templates/layouts/base.html](app/templates/layouts/base.html) includes a viewport meta tag.
- The page uses shared responsive CSS and server-rendered HTML, which is generally compatible with mobile rendering.

### Findings
- There is no sign of a mobile-specific blocker in the HTML structure.
- No browser-level mobile rendering test was executed in this audit, so the mobile assessment is based on the server-rendered markup and responsive template structure rather than a real-device screenshot test.

### Assessment
- The current implementation appears mobile-compatible at a structural level.
- A browser-based mobile check would still be a useful final validation step.

## Key SEO Risks

1. Structured data is not fully aligned with Learning Center URLs.
2. Breadcrumb schema and page breadcrumb labels do not fully reflect the Learning Center taxonomy.
3. Internal links are not implemented as true anchor links, weakening crawl depth and topical relevance.
4. Article-level canonical metadata is not being honored by the Learning Center route layer.

## Overall Assessment

The Learning Center is discoverable, crawlable, and renderable by search engines. The current implementation is suitable for a first-pass SEO rollout, but it is not yet fully optimized for search-engine understanding of the Learning Center as a dedicated content hub.

## Recommended Next Steps

- Align Learning Center JSON-LD with /learning routes rather than blog routes.
- Use Learning Center-specific breadcrumb labels in the schema and page navigation.
- Replace plain-text related-content cards with real links.
- Respect article-level canonical values from the JSON content when building page metadata.
